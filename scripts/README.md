# Scripts

Two scripts, both self-sufficient: each resolves the repository root itself and each
can be run alone from anywhere.

| Script | What it does |
|---|---|
| `setup.sh` | One-command onboarding. Prerequisites → `.env` → generated database password → optional pre-commit hook → restore and build. |
| `ci-local.sh` | Runs the CI jobs from `.github/workflows/ci.yml` locally, so a red build is debuggable without pushing. |

```bash
./scripts/setup.sh
./scripts/ci-local.sh                       # every job
./scripts/ci-local.sh test compose-smoke    # just these
```

## Environment variables

Everything is read from the gitignored `.env`, which `setup.sh` creates from
`.env.example`. Nothing here reads a literal credential, and nothing here should
ever be changed to.

| Variable | Tier | Used by | Comes from |
|---|---|---|---|
| `POSTGRES_PASSWORD` | always required | `docker compose`, `ci-local.sh compose-smoke` | generated by `setup.sh` |
| `POSTGRES_USER` | always required | `docker compose` | `.env.example` default |
| `POSTGRES_DB` | always required | `docker compose` | `.env.example` default |
| `WEB_PORT` | optional | `docker compose`, `compose-smoke` | defaults to 8080 |
| `API_PORT` | optional | `docker compose`, `compose-smoke` | defaults to 5081 |

Deployed environments do **not** read `.env`. They get the same values from platform
secrets — see [`../flyio/SECRETS.md`](../flyio/SECRETS.md), which is the authoritative
description of where each value lives once the code leaves a laptop.

## Deployment

There are no deploy scripts here, deliberately. Deployment is
`.github/workflows/flyio.yml`, triggered by pushing a tag, and app creation, volume
creation and secret setting all happen inside it. The alternative — a local script
that provisions — is how an app ends up with settings that exist in someone's shell
history and nowhere in git.

To operate the deployment by hand:

```bash
flyctl logs      -a blackholesim-api
flyctl status    -a blackholesim-api
flyctl secrets list -a blackholesim-api          # names and digests; values never read back
flyctl proxy 15432:5432 -a blackholesim-postgres # reach the database from here
```

Scaling and teardown are the `Fly.io scale` and `Fly.io destroy` workflows in the
Actions tab, not commands typed here.

## Troubleshooting

Keyed on the literal text you will see, because that is what gets pasted into a
search box.

| What you see | What it means | Fix |
|---|---|---|
| `Npgsql.NpgsqlException … Failed to connect to 127.0.0.1:5432` | No database is running; the API fell back to the `appsettings.json` localhost default. | `docker compose up db`, or run the AppHost, which starts one. |
| `Migrations still running` in `/health` | Normal for a few seconds after boot. Persisting means the database is unreachable. | `docker compose logs api` — the migration service logs each retry and why. |
| `Database migration failed after 10 attempts` | The API is up and deliberately staying up so it can report this. The schema is unusable. | Check the connection string, then `docker compose logs api` for the underlying error. |
| `relation "RenderJobs" does not exist` | Something queried before migrations finished. | Should be impossible — `DatabaseReadyGate` gates it. If you see it, that gate was bypassed. |
| Browser console: `blocked by CORS policy` | The frontend's origin is not in the API's allowlist. | Set `Cors__AllowedOrigins__0` to the frontend's exact origin, scheme and port included. |
| Frontend calls `localhost` in a deployed environment | `API_BASE_URL` was not set, so the entrypoint wrote the fallback. | Check `[env]` in `flyio/blackholesim-web.fly.toml`, then `curl https://<web>/appsettings.json`. |
| `exec /docker-entrypoint.d/30-blackholesim-config.sh: no such file or directory` | The script has CRLF line endings; the `\r` becomes part of the interpreter path. | `.gitattributes` pins `*.sh` to LF — re-clone or run `git add --renormalize .`. |
| `initdb: directory "/var/lib/postgresql/data" exists but is not empty` | `PGDATA` is pointing at the mount root, where `lost+found` lives. | It must be a subdirectory; see `flyio/blackholesim-postgres.fly.toml`. |
